# 引継資料: 練習計画UX改善（日付/曜日/空週/Enter/コピー）（2026-07-13）

## 概要

### このセッションで達成したこと

練習計画ツールを開いたときの初期体験と、日々の入力体験を改善した。画面を開くと今日または今日に最も近い練習日が既定で選ばれ、今日を含む週が最初から表示される（保存されている週起点・アーク月・週番号そのものは書き換えない、表示専用の解決）。曜日は月・日を含む全7曜日で入力できるようになり、今日の週がまだ何も入力されていない空の状態でも、曜日見出しや空セルをタップしてその日の入力に進める。目標編集（週・月・年アークの見出し）はEnterキーでの誤保存をやめ、明示の保存ボタン経由に統一した（日本語入力の変換確定Enterで意図しない保存が起きる不具合の修正）。「他の日からコピー」機能は、コピー元の候補が表示中の4週間だけに限定されていた欠陥を直し、テナント内の保存済み全日から選べるようにした。あわせて、このコピー拡張作業の過程で作り込んでしまった「ねらい・コート等の既定値が編集フォーム/コピー内容から欠落する」回帰（独立レビューがHigh指摘として検出）を根治し、回帰テストを追加した。

いずれも本番（https://ai-bb-coach.web.app ）へ反映済み。

### なぜやったか

オーナーから「月・日に練習を入れたい」「開くたびに今週まで週送りするのが手間」「目標欄で日本語変換中にEnterを押すと変換途中の文字で保存されてしまう」「前は使えていた『他の日からコピー』が使えなくなっている（ように見える）」という複数の指摘を受けた。調査の結果、コピー機能自体はコード上削除されておらず、表示範囲を絞る既存の設計（コピー元候補＝表示中4週間限定）と、今回改修した「今日を含む週を既定表示にする」機能が組み合わさることで、コピー元にしたい日（表示範囲外）が候補から見えなくなる現象だったと判明した。

## 実装した機能

### (A) 全7曜日を入力可能に

新規テナントの既定スケジュールに月・日を追加し（水・木と同型：半面・コーチ不在）、UI側の週グリッドも曜日数を動的に扱うよう是正した。**既存テナントの本番データは無変更**（スケジュールは払い出し時に1回書き込まれるだけで、以後の書き換えAPIが存在しないため）。既存チームでも表示補完だけで月・日が入力導線つきの空状態セルとして出る。

**主要ファイル**

| ファイル | 役割 |
|---|---|
| `functions/tenant-template.mjs` | 新規テナント払い出し時の既定 `schedule` に月・日を追加 |
| `engine/data/config.sample.json` / `engine/data/config.girls.sample.json` | ローカル/CLI用フィクスチャに同内容を反映 |
| `ui/plan-data.mjs` | `padToFullWeek()`（scheduleに無い曜日を月〜日7曜日ぶんへ表示専用で補完） |
| `ui/pattern-timeline.mjs` | 週グリッド列数をCSS変数 `--wg-cols` 駆動に変更（5列固定を撤去）、曜日見出しを動的生成 |

### (B) 今日に最も近い練習日を既定選択

「今日と完全一致する日があればそれ、無ければ今日との暦日差が最小の候補（同点は暦日の性質上発生しない、今日が練習の谷間なら未来優先・未来が無ければ直近過去）」に置換。週起点未設定テナント（候補ゼロ）は従来どおりの静的初期表示を維持。

**主要ファイル**: `ui/render-shared.mjs`（既定表示日を選ぶ処理）

### (C) 開いたら今日を含む週/月を表示

`week_start_date`・`current_month`・`week_of_month`（保存されている週起点・アーク月・週番号）は書き換えず、表示専用の「表示アンカー」を別途都度計算し、週/月ピッカーと年リボンの「いま」マーカーの生成元だけをそちらに差し替えた。アーク月境界をまたぐ場合は月（フェーズ）表示も連動して繰り上げ/繰り下げる。

**主要ファイル**: `ui/plan-data.mjs`（`resolveDisplayAnchor()` / `serverTodayISO()` / `diffDaysISO()` / `mondayOfISO()` / `FULL_WEEK_DAYS`、`buildPlanData` への `today` 引数追加）

### (D) 空週でも入力可能なグリッドを表示

(C) により「今日を含む週」が既定表示になった結果、その週がまだ無入力だと従来は文字メッセージだけになっていた（週グリッドが描画されない）。実日付のある曜日が1つでもあれば、既定時間軸（平日夕方枠）で7列の週グリッドをそのまま描画し、空セルは日入力画面へのジャンプ導線（「＋ 入力」）にした。真に導線不能な面（週起点未設定テナント）だけは従来どおり文字メッセージに残した。

**主要ファイル**: `ui/pattern-timeline.mjs`（週ビュー描画関数 `weekLevel` の空短絡分岐是正＋空セルCSS）

### (E) 目標編集のEnter誤送信を廃止

週・月・年アーク見出しの目標編集で共有されている入力欄から、Enterキーでの保存トリガーを削除。日本語IME変換確定のEnterで変換途中の文字がそのまま保存される不具合を修正し、保存は明示の「保存」ボタンに一本化した。対象欄はどの`<form>`にも属さないため、Enter配線を削除しても暗黙のフォーム送信は発生しない。1箇所の修正で週・月・年の目標欄すべてに反映される（共有IIFEのため）。

**主要ファイル**: `ui/goal-editor.mjs`（keydownリスナー1行を削除）

### (F) メニューコピー元を保存済み全日に拡張・回帰修正

**主要ファイル**

| ファイル | 役割 |
|---|---|
| `ui/plan-data.mjs` | コピー元候補 `allCoachDays` を「表示中4週間限定」から「テナント内の保存済み全日」に拡張。あわせて、拡張時に空オブジェクトを土台にしていたため生じた「ねらい・コート等の既定値欠落」回帰を、曜日別の既定値テンプレ（表示が使うのと同じテンプレ）を土台にする形へ是正 |
| `ui/editor.mjs` | 編集フォームのコピー元候補生成（`editorDataIsland`）の参照先を `allCoachDays` に変更。候補が0件のとき（テナント全体で保存済み日が無い場合のみ）案内文を表示するよう追加 |
| `ui/default-blank-autofill.test.mjs` | 「表示内容とフォーム/コピー内容が一致する（空欄にしない）」ことを検証する回帰テストを追加 |

土曜合同・火金組違い・保存アンカー（週起点等）のロジックはA〜Fいずれの機能でも変更していない。

## 既知の注意点・未対応項目

1. **（最優先）strategy本番のログイン後実画面をオーナーが目視確認する必要がある**。今日選択・全7曜日入力・空週グリッド・メニューコピー・Enter保存の4点。メインはGoogleログインの都合で本番のログイン後画面を直接確認できていない。
2. **「今日を含む週」への追従は表示アンカー自体を自動更新する仕組みではない**。表示の初期位置だけを毎回「今日を含む週」から動的に計算する設計であり、保存されている週起点・アーク月・週番号そのものは変更していない。今日が保存アンカーの表示範囲外になった場合は、既定選択の練習日も「表示されている範囲内で今日に最も近い日」に留まる（最近接フォールバック）。
3. **ai-basketball-coach側の改善バックログは未着手のまま継続**（前セッション引継分）: 試合後分析のフル要素対応（着手前にPdM確認が必要）、ショット分類の永続化配管の撤去、ボーナス下でのフリースロー本数入力のUX改善、新規に見つかったバグ4件、直書きされている色指定15箇所のトークン化、孤立したworktreeの掃除（オーナーの明示go待ち）。
4. **副次的に見つかった既存不具合（今回のスコープ外・未着手）**: 週グリッドで5分未満の極小ブロック（例: リバウンド枠）が上下のカードに視覚的にめり込む描画崩れが、今回touchしていない時間軸計算ロジックに、曜日数と無関係に既存している。

## 開発中に得た教訓

1. **何が起きたか**: 既定の表示範囲（今日を含む週）を変えたことで、その表示範囲にスコープされた別の既存機能（メニューコピー元候補＝表示中4週間限定という既存設計）が無言で機能不全になった。オーナーが体感した「コピーが消えた」の真因はここにあり、コードの削除やregressionではなかった。
   **再発防止**: 既定ビュー・表示範囲を変更するときは、その範囲を参照している他機能を全探索してから実レンダで確認する。
   **反映先候補**: 既定表示変更を伴う改修のレビュー観点に「表示範囲スコープの機能への影響探索」を追加する。

2. **何が起きたか**: コピー機能のデータ土台を空オブジェクトにしたところ、表示側が使っている既定テンプレ（曜日別の既定ねらい文・場所等）が引き継がれず、ねらい未保存日で編集フォーム/コピー内容が空欄になるHigh回帰を生んだ。
   **再発防止**: prefill・コピーのデータ土台は、表示が使う既定テンプレと同じ土台からマージして作る。「表示内容＝フォーム/コピー内容（非空）」を回帰テストで固定する。
   **反映先候補**: 同種の新規prefill/コピー機能を実装する際のレビュー観点。

3. **何が起きたか**: 日本語IME変換確定のEnterキーイベントがそのまま保存トリガーに直結しており、変換途中の読みがそのまま保存される不具合があった。
   **再発防止**: フォームが存在しない単一行入力では、Enterキーの配線自体を削除し保存はボタン駆動に統一する（IME判定を足す対処より配線削除の方が単純で確実）。
   **反映先候補**: 日本語自由記述入力を新設する際の標準実装パターン。
