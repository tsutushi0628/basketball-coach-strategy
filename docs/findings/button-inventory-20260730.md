# 押せる部品の棚卸しと見た目の収束先（2026-07-30）

## 結論

実装側に押せる部品が53型あり、その見た目が8系統に割れていた。
8系統のうち3つが2役割以上を兼ねており、最も混同を生んでいたのはアクセントの面塗りである。
アクセント面塗りは「いま選ばれている状態」と「保存する操作」の両方に使われていた。

役割の定義を起こし直した結果、押せる部品の見た目は7系統へ収束する。
系統の数は8から7へ1つ減るだけだが、1つの系統が運ぶ役割の数は最大3から1になる。
規律の正本は `docs/design-system/component-spec.md`、値の正本は `ui/styles/tokens.css` である。

## 棚卸しの過程で見つかった別の欠陥

いずれも今回の成果物では直さない。優先度つきで残す。

なお冒頭に挙げた2件は定義側で解決済みで、実装フェーズは是正された定義に従えばよい。

**解決済み（定義を修正）**：進行中を示すチップの女子側が、どのテーマでも読めない。
プリセットが差し替えるのはアクセント6変数（`ui/color-presets.mjs:46`）で、女子の文字色は含まれない。
一方で女子の識別色そのものは差し替えられる（同ファイル21-36行）。
このチップは実際に生成されている（`ui/render-shared.mjs:328`、ラベルは「いま男子の時間」「いま女子の時間」）ので、潜在的な不具合ではなく現に出ている不具合である。
既定テーマでのコントラスト比は1.42で、暗い側のテーマでも2.15にとどまる（該当箇所は `ui/styles/base.css:157`）。
男子側は5.68で問題ない。
識別色の面の上に文字を置くのをやめ、カード面の上に本文前景で置く形へ定義を変えた（実測15.31）。
さらに進行中チップは専用の面と枠も持たせず、素の識別チップと同形にしたうえで、その日の見出しの直後へ移した。
操作の列に置くと、押せない標識が押せるボタンの並びに混ざる。
既に動いている男女チップ（`ui/styles/base.css:43-46`）と同じ形なので、新しい部品を作る必要はない。

**解決済み（定義を修正）**：破壊的操作の文字色がAAに届いていない。
削除と取り消しの文字に使われている色はカード面の上でコントラスト比4.17で、4.5に届かない。
同じ色相の濃い側が既にトークンとして存在し、そちらなら5.86になる。
役割3の文字色は濃い側を指すよう定義した。

**中**：汎用ボタンの土台定義が3箇所に重複している。
共通CSS（`ui/styles/base.css:10`）、認証画面CSS（`ui/styles/auth-page.css:23`）、生成された一覧画面（`ui/index.html:25`）で、内側余白と文字の太さと無効時の扱いが食い違う。
認証画面側だけが無効時と押下時の見た目を持つ。

**中**：日付移動のボタンが日付ピッカーの選択チップと同じクラスを共有している。
日送り、週送り、月送りは日ピッカーのチップ（`ui/styles/pattern-timeline.css:280`）を土台に使っており、役割1と役割5が同一クラスに同居している。
役割を分けるときはクラスの分離が必要になる。

**低**：男子の識別色はどのプリセットでもアクセントと同値である（`ui/color-presets.mjs:21-36` の16行すべてで一致）。
プリセットの書き出し対象に入っているため今回は畳まなかったが、書き出し側を1変数減らせば整理できる。

**低**：曜日タブの孤立した定義が残っている。
`ui/_mock-day.html:132-137` の曜日タブは、どの本番HTMLからもテストからも参照されておらず、見た目の定義もライブ実装と食い違う（枠線を持たず影を使う）。

## 付け替えの規模

部品CSS7ファイルで、色を伴う宣言が色プリミティブを直参照している箇所は375件ある。
内訳は共通CSSが118件、週表示のCSSが98件、認証まわりが47件と27件、行編集が41件、目標編集が28件、チーム選択が16件である。
このうち押せる部品に当たるのが今回の付け替え対象で、残りはカード面、見出し、曜日の着色などである。
意味ロール層を通す付け替えが済んだ時点で、この375件が0に近づく。
