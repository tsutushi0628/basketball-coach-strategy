# 過去の週への移動とコピー元選択のサービス設計

対象リポジトリ: basketball-coach-strategy（このリポジトリのルート）。
本文中のパスはリポジトリのルートからの相対で書く。

この文書は、オーナー（バスケ部コーチ）の要望2件をタッチポイントと業務フローに落とし、後段の ux-designer（HTMLモック）と architect（技術設計）へ渡す。
アプリ本体のコードは変更していない。

要望の原文は次の2つである。

> 日付表示のUIは悪くないんだけれど、これ過去にいけなくね？ 過去の週を選べるUX追加して

> 他の日からコピー機能も機能はいいんだけれど、履歴がずいぶん多くなってきた。これも最適なUX提案して追加して

前者は週タブの意匠を保ったまま移動手段だけを足す。
後者は既存の3択（男女オンリーの切り替え）と反転コピーの並びを保ったまま、コピー元の選び方だけを組み直す。

---

## 0. 結論

**要望1（過去の週）**: 週タブの列はいまの4枠のまま、列の左右に「前の週」「次の週」の一歩移動を足し、列の外に「年月で飛ぶ」長距離移動と「今週へ戻る」導線を足す。
4枠は週の連なりの上を滑る窓として動き、今週を含まない位置にいるあいだだけ「今週へ戻る」が現れる。
過去の週では、上書きのある日は普段どおり見て編集でき、上書きのない日は「記録なし」として入力導線だけを出す。
叩き台の自動入力は過去の週では出さない。
週の目標はその週のキーで編集できる。
月の目標は、表示中の週が今日と同じ学校年度（4月始まり）に入っていればその週の月をキーにして表示と編集ができ、年度の外なら出さない。

**要望2（コピー元）**: 「他の日からコピー」の中を「おすすめ」と「探す」の2枠に分ける。
「おすすめ」は最大3件（直近の同じ曜日、前回の練習日、去年の同じ頃）を関係語つきで並べ、「探す」は年月で絞ってからその月の日を選ぶ。
取り込みの動作（日付と曜日を保ち、時間割と項目だけ複製し、目標は来ない）と確認の流れは変えない。

相談役（fable-advisor）の異見は両方とも採った。
週配列の先頭は今週のまま固定し、先頭週の月目標のキーは今日のアーク月のままにする（他の週の月セルはその週の月のキーを持つ）。
過去の週は上書きの閲覧と編集だけにし、空の日は自動入力せず「記録なし」で出す。
コピー元は推奨を少数に絞り、年月の絞り込みで前年の同じ時期へ届くようにする。

## 1. 前提となる現状

設計の土台になる事実を、コード上の位置とともに固定する。
ここに書いていない挙動は変えない。

### 1.1 週の生成と表示

- `ui/plan-data.mjs:143-158` `computeWeekPeriods` は、アンカー週から +7日ずつ4週（今週と先の3週）だけを生成する。
- `ui/plan-data.mjs:954-975` `resolveDisplayAnchor` は、表示アンカーを毎回「今日を含む週の月曜」に寄せる。
- `ui/plan-data.mjs:1059` は先頭週（`weeks[0]`）を `days`、`session`、`goalKeys` の土台として展開する。
- `ui/plan-data.mjs:1040-1043` は既習レクチャを先頭週から順に週送りで連鎖させる。叩き台（seedDays）はこの連鎖の産物である。
- 週は SSR で4週ぶんを全部描き、クライアントが `hidden` を切り替える（`ui/pattern-timeline.mjs:856-869`）。
- 週タブは日レベル（`dayWeekSelector`、`ui/pattern-timeline.mjs:810-817`）と週レベル（`weekPicker`、同 `819-826`）の2箇所にあり、どちらを押しても `ui/render-shared.mjs` の `selectWeek` 1箇所で両方の選択状態が揃う。
- 週の保存キーは月曜のISO日付、表示は日曜始まりである（`ui/plan-data.mjs:147-148`）。日曜始まりの週にも月曜がちょうど1つ含まれるので、キーと表示週は1対1に対応する。
- 月ピッカー（`ui/pattern-timeline.mjs:829-836`）は今月から先の6ヶ月を `yyyy/mm` のタブで並べる。過去の月は無い。

### 1.2 目標のキー

- 週の目標は週ごとに `weekStartDate`（その週の月曜ISO）をキーに保存される（`ui/render-shared.mjs:278-280`）。週を切り替えれば正しい週のキーへ書く。
- 月の目標はアンカーのアーク月 `monthArcKey`（`ui/plan-data.mjs:1122-1124`）をキーに保存される（`ui/render-shared.mjs:275-277`）。キーは「1」から「12」のアーク月で、年を持たない（`functions/index.mjs:299`）。
- 目標を保存すると `location.reload()` で全タブを揃える（`ui/goal-editor.mjs:47`）。日の上書きを削除した後も同じく再読込する（`ui/editor.mjs:1245`）。
- 初期表示は今日に最も近い練習日へクライアントが寄せる（`ui/render-shared.mjs:560-575`）。

### 1.3 コピー元の候補

- `ui/editor.mjs:479-499` `copyFromOptions` は、テナント内の全コーチ上書き日（表示中の週に限らない、`ui/plan-data.mjs:1137-1164` `allCoachDays`）を日付昇順で1つの `<select>` に並べる。上限も絞り込みも検索も無い。
- ラベルは「YYYY/MM/DD（曜）：タイトル」、タイトルが無ければ「：ねらい」、どちらも無ければ日付だけである（`ui/editor.mjs:255-265`）。
- 取り込み（`ui/editor.mjs:776-784`）は、編集中の日の日付と曜日を保ったまま、ねらい、コート、時間割と項目を複製する。週や月の目標は来ない。中身がある状態では上書き確認を挟む。
- 編集パネルの並びは「男女オンリーの3択、ドリル候補、他の日からコピー、自動の叩き台、この日のねらい、コート、時間行」である（`ui/editor.mjs:612-620`）。反転コピーは各時間行の右上にある（同 `570-573`）。

### 1.4 空の日の表示

コーチが入力していない日は叩き台を出さず、「まだ入力がありません。この日の練習を入力してください。」の空状態と、「入力する」「叩き台を読み込む」の2導線を出す（`ui/pattern-timeline.mjs:738-752`、`ui/plan-data.mjs:750-776`）。

### 1.5 シーズン構造

年度は4月に始まり、夏の大会（6〜7月）で3年生が引退し、1〜2年生の新チームが夏に始動する。
新チームの主目標は区の新人大会（11〜12月）、都の新人大会（1〜2月）、3月の研修大会である。
男子は夏の大会が長引きやすく新チームの始動が遅く、女子は早く代替わりする。
男女で山がずれるので、「去年の同じ頃」を見返す動機は男女で別の週に落ちる。
正本は `docs/practice-knowledge/reference/チーム基本情報.md`「シーズン構造と代替わり」。

## 2. 要望1 過去の週を選べる

### 2.1 カスタマージャーニー

登場人物はコーチ1人である。
閲覧は体育館でスマホという場面が既存調査に書かれている（`docs/findings/research-20260609-scheduler-ux.md:112`）。
計画の入力は練習の前夜から当日朝に自宅で行う前提で、PCとスマホの両方を対象にする。
過去の週を開く動機は次の3つで、いずれも「今週を組む」か「記録を残す」の前後に現れる。

| 場面 | いつ | 何のために | 端末 | 移動の距離 |
|---|---|---|---|---|
| A 先週の振り返り | 日曜夜か月曜朝、今週を組む前 | 先週どこまでやったかを見て今週の続きを決める | 自宅PCかスマホ | 1週 |
| B 大会前の参照 | 新人大会の3〜4週前（10月末から11月）、夏の大会の1ヶ月前（5月から6月） | 去年の同じ時期にどう組んだかを見て今年の山を作る | 自宅PC | 約52週 |
| C 記録の補填 | 練習の翌日以降 | 先週やった内容を後から書き残す | スマホ | 1〜2週 |

場面Bは男女で週が違う。
女子は7月中に新チームへ移り、男子は都の大会が終わる7月下旬以降に移るので、「去年の代替わり直後」を見返す週も男女で別である。
移動手段は1つの週を選ぶだけでよく、男女の切り替えはその週の中の既存表示（男女2列）が担う。

タッチポイントの前後は次のとおりである。

1. 日レベルを開く。初期表示は今日に最も近い練習日（既存）。
2. 週タブの列の左端「前の週」を押す。窓が1週戻り、その週の既定日（先頭の練習日）が見える。今週を含まない位置なら「今週へ戻る」が現れる。
3. 遠い週へ行くときは「年月で飛ぶ」を使う。年月を選ぶと窓がその月の第1週に合い、第1週の既定日が見える。
4. 見終わったら「今週へ戻る」を押す。窓が今週を先頭にした位置へ戻り、今日に最も近い練習日が見える。
5. 場面Cで過去の日に入力して保存すると、保存の後も同じ日が見えている（2.5節）。

### 2.2 状態一覧

窓（4枠）の位置、選んでいる週、選んでいる日の3軸で状態を切る。

| 軸 | 値 | 見え方の違い |
|---|---|---|
| 窓の位置 | 今週を含む | 「今週へ戻る」を出さない。「次の週」は窓の末尾が今週＋3週なら押せない |
| | 今週を含まない（過去側） | 「今週へ戻る」を出す。「前の週」は窓の先頭が到達下限なら押せない |
| 選んでいる週 | 今週 | 現状どおり |
| | 未来週（今週＋1〜3週） | 現状どおり（叩き台の導線あり） |
| | 過去週（今日と同じ学校年度） | 月の目標セルはその週の月のキーで表示と編集ができる。叩き台の導線を出さない。空の日は「記録なし」 |
| | 過去週（前の学校年度以前） | 月の目標セルを出さない。叩き台の導線を出さない。空の日は「記録なし」 |
| 選んでいる日 | 上書きあり | 現状どおりの手書き表示。編集、印刷、テキストコピー可 |
| | 上書きなし（過去週） | 「記録なし」の空状態と「この日の記録を入力する」の1導線 |
| | 上書きなし（今週か未来週） | 現状どおり（「入力する」「叩き台を読み込む」の2導線） |
| テナントの週起点 | 未設定 | 実日付が無いので過去移動を出さない（現状の単一週フォールバックのまま） |

「今週を含まない」は過去側だけである。
未来側は今週＋3週で止まるので、窓が今週を含まない未来側の位置は存在しない。

学校年度は4月1日から翌年3月31日までとし、週がどちらの年度に入るかは週の保存キー（月曜）の日付で決める。
3月末と4月初めをまたぐ週は月曜の側の年度に入る。

### 2.3 到達範囲

- 過去の下限は「そのテナントで最も古い上書き日を含む週」と「今週の4週前」のうち早い方とする。
  上書きが1件も無い新しいテナントでも4週は戻れ、直近の書き忘れを補填できる。
  最も古い上書きより前は全部「記録なし」なので、そこへ行けても得るものが無い。
- 未来の上限は今週＋3週のまま変えない。オーナーの要望は過去である。
- 「年月で飛ぶ」の選択肢は到達範囲内の年月だけを出す。範囲外の年月を選べてしまい空の週に落ちる状態を作らない。

### 2.4 過去の週での許可操作

| 操作 | 過去週 | 根拠 |
|---|---|---|
| 上書きのある日の閲覧、印刷、テキストコピー | 可 | 振り返りの中核。読み取りだけなので副作用が無い |
| 上書きのある日の編集と保存 | 可 | 記録の補填（場面C）。保存先は実日付の文書IDで、今日と過去の区別が無い（`functions/index.mjs` の `/api/override`） |
| 上書きのない日への新規入力 | 可 | 同上。導線は「この日の記録を入力する」の1つ |
| 叩き台の読み込み | 不可（導線を出さない） | 叩き台は先頭週から前進する既習連鎖の産物で、過去の週に生成すると既習が矛盾する（1.1節）。過去の週は上書きだけで組む |
| 週の目標の編集 | 可 | キーがその週の月曜ISOなので正しい週へ書ける（1.2節） |
| 月の目標の表示と編集（今日と同じ学校年度の週） | 可 | キーをその週の月（アーク月）にする。現状の今日のアーク月固定のままだと、過去週で保存すると今日の月へ書いてしまうので、週ごとにキーを持たせる。3週前を見ながら今月の目標を直す場面は普通にあり、一律に消すと不便である |
| 月の目標の表示と編集（前の学校年度以前の週） | 不可（セルを出さない） | アーク月のキーが年を持たないので、去年の同じアーク月の目標は今年の値と同じ文書になり、表示しても去年の内容にならない |
| 上書きの削除 | 可 | 現状の確認カードのまま |

年度外の週で月の目標のセルを消す代わりに、その週の「週の目標」だけを目標バーに残す。
目標バーの2セル構成を1セルにするのは意匠の変更ではなく、正しく書けない入口を閉じる措置である。

### 2.5 保存後の表示

目標の保存と上書きの削除のあとに `location.reload()` すると、初期表示が今日に最も近い練習日へ寄り、過去の週で保存したコーチは今週へ飛ばされる。
この再読込は別件（不具合3）の対応で廃止が決まっており、日の上書き保存（`ui/editor.mjs:1163`）と同じくその場で差し替える形になる。
本設計はその廃止を前提にし、保存と削除のあとも見ていた日がそのまま見えていることを要件にする。
再読込を残したまま過去週の編集を出荷すると場面Cの流れが毎回切れるので、順序は「再読込の廃止が先、過去週の編集の出荷が後」である。

### 2.6 失敗フロー

| 失敗パターン | 影響 | 扱い |
|---|---|---|
| 「前の週」を到達下限で押す | 何も起きない | ボタンを押せない状態にして、押せる印象を与えない |
| 年月で飛んだ先の月に上書きが1件も無い | 全日「記録なし」 | 到達範囲内なら許す（下限が「最古の上書き」か「4週前」なので、範囲内の空の月は下限付近の高々4週に限られる） |
| 過去の日を今週の日と取り違えて入力する | 誤った日に記録が残る | 「今週へ戻る」が過去側でだけ現れ、位置の手がかりになる。編集パネルの見出しにはその日の日付と曜日が出ている（既存）。それでも取り違えたら既存の削除で戻す |
| 今日と同じ年度の過去週で月の目標を書く | 今日の月へ書いてしまう（現状のキー固定のまま出荷した場合） | 月セルのキーをその週の月にする。先頭週以外の週でキーが今日の月のままになっていないことをテストで固定する |
| 前の年度の週で月の目標を書こうとする | 今年の同じアーク月へ書く | 入口を出さないので起きない |
| 週起点未設定のテナント | 実日付が無い | 過去移動を出さない（2.2節） |
| 過去週の描画量が多い | 初期表示が重くなる | 到達範囲の下限で件数に上限がつく。描画をまとめて出すか必要な週だけ出すかは architect の判断 |

### 2.7 影響範囲

- `ui/plan-data.mjs`: 週の配列に過去週を足す。先頭は今週のまま（`weeks[0]` の展開と `goalKeys` は不変）。過去週の日は叩き台を作らず、既存の `allCoachDays` と同じ曜日テンプレを土台に上書きだけを合流する。
- `ui/pattern-timeline.mjs`: 週タブ列（2箇所）の左右に一歩移動、列の外に年月ジャンプと今週へ戻る。過去週の空の日の文言と導線。
- `ui/render-shared.mjs`: `goalsBar` の月セルを週ごとのキーで出し、年度外の週では出さない。`selectWeek` を単一の持ち場のまま窓の移動に対応させる。
- `ui/goal-editor.mjs`、`ui/editor.mjs`: 保存と削除のあとの再読込を廃止する（不具合3の対応に含まれる）。本設計はその上に乗る。
- `functions/index.mjs`、Firestore: 変更しない。読む範囲は既にテナント全件である。

## 3. 要望2 コピー元の選び方

### 3.1 カスタマージャーニー

コーチが編集パネルを開くのは、その日の練習を組むときである。
一から書くより「前にやった日を持ってきて直す」ほうが早い日が多く、そのときの探し方は3通りある。

| 場面 | 探し方 | 例 |
|---|---|---|
| D 曜日固定の練習 | 直近の同じ曜日 | 火曜は半面で組む決まりなので、先週の火曜を持ってくる |
| E 前回の続き | 前回の練習日 | 直前の練習でやった流れを引き継いで少し変える |
| F 去年の同じ時期 | 前年の同じ頃 | 新人大会の3週前に、去年の同じ3週前の日を持ってくる |

場面Dが最も多い。
場面Fは年に数回だが、一覧を1年ぶんさかのぼる負担が最も大きい。
それ以外（記憶にある特定の日）は年月で絞ってから探す。

タッチポイントの前後は次のとおりである。

1. 日レベルで対象の日を開き、「編集」を押す。パネルの見出しにその日の日付と曜日が出る。
2. 男女オンリーの3択の下、「他の日からコピー」に「おすすめ」の候補が最大3件並ぶ。
3. 場面DとEは「おすすめ」から1件を選び、「この日を取り込む」を押す。中身があれば上書き確認が出る（既存）。
4. 場面Fと特定の日を探すときは「探す」で年月を選び、その月の日から1件を選んで同じボタンを押す。
5. 取り込んだ内容を直して保存する。

### 3.2 状態一覧

| 候補の数（編集中の日を除く） | 見え方 |
|---|---|
| 0件（テナント全体で保存済みの日が無い） | 現状の案内文「コピーできる保存済みの日がまだありません。他の日を保存すると、ここから選べるようになります。」 |
| 0件（保存済みが編集中の日だけ） | 現状どおり何も出さない |
| 少数（おすすめに全部載る） | 「おすすめ」だけ。「探す」は出さない |
| 多数（おすすめに載らない日がある） | 「おすすめ」と「探す」の両方 |
| 去年の同じ頃が無い（データが1年未満） | 「おすすめ」がその1件ぶん短くなる。空の枠は出さない |
| おすすめの候補が重なる | 同じ日を2回出さず、先に該当した関係語1つで出す |

### 3.3 情報設計

**基準日**は編集中の日である。
おすすめは基準日より前の日から選ぶ。
基準日より後の日（先の週にすでに書いた計画）は「探す」の年月に含める。

**おすすめ**は次の3件を上から順に置き、重なりは先の項目に寄せる。

| 順 | 関係語 | 定義 |
|---|---|---|
| 1 | 直近の同じ曜日 | 基準日より前で、同じ曜日の最も新しい上書き日 |
| 2 | 前回の練習日 | 基準日より前の最も新しい上書き日 |
| 3 | 去年の同じ頃 | 基準日の364日前（同じ曜日の1年前）を中心に前後3週の中で、同じ曜日を優先し、最も近い上書き日 |

3件を超えて増やさない。
4件目以降は「探す」の仕事であり、おすすめが増えるほど選ぶ負担が「探す」に近づく。

おすすめのラベルは「関係語　YYYY/MM/DD（曜）：タイトル」で、タイトルが無ければねらい、どちらも無ければ日付までにする（既存のラベル規則を関係語の後ろに置く）。
例: 「直近の火曜　2026/08/25（火）：シュート強化」。
関係語の「同じ曜日」は実際の曜日名で書く（「直近の火曜」）。

**探す**は年月で絞ってから日を選ぶ2段である。

- 年月の選択肢は上書きのある年月だけ、新しい順に並べる。上書きの無い月は出さない。
- 初期の年月は、基準日の月に候補があればその月、なければ最も新しい月。
- 日の選択肢はその月の上書き日を日付順に並べ、ラベルは「D日（曜）：タイトル」とする。年月は上で選んでいるので繰り返さない。
- 曜日の絞り込み軸は足さない。1ヶ月の上書き日は多くて20件前後で一覧できる。曜日の要件はおすすめ1件目が受ける。

選んだ後の動作は現状のまま、「この日を取り込む」の1ボタンと上書き確認である。
おすすめと探すのどちらで選んでも同じボタンに集約し、取り込みの入口を2つにしない。

### 3.4 失敗フロー

| 失敗パターン | 影響 | 扱い |
|---|---|---|
| 曜日の違う日を取り込む | 時間割はそのまま複製され、コートなどが合わない | 現状どおり許す。日付と曜日は編集中の日のまま保たれ、直す前提の取り込みである |
| おすすめの日と探すの日を両方選んでから押す | どちらを取り込むか曖昧 | 選択は1つの持ち場にまとめ、後から選んだ方が前の選択を外す |
| 中身があるところへ取り込む | 上書き | 現状の確認のまま |
| 去年の同じ頃が男女の代替わりで意味を持たない週 | 去年のその週は前チームの練習 | 関係語に「去年の同じ頃」と日付が出るので、コーチが判断できる。除外の規則は作らない（男女で時期が違い、機械判定が外れやすい） |

### 3.5 影響範囲

- `ui/editor.mjs` `copyFromOptions`: 1つの `<select>` を「おすすめ」と「探す」に分ける。候補源 `PREFILL` は不変。`copy-from` の処理と確認は不変。
- `ui/plan-data.mjs` `allCoachDays`: 変更しない（既にテナント全件を持つ）。
- サーバとFirestore: 変更しない。

## 4. やらないこと

- 週タブの意匠を変えない。ドロップダウン化もカード化もしない。足すのは移動手段だけである。
- 月レベルと年レベルの過去移動は足さない。月ピッカーは今月から先の6ヶ月のまま。
- 過去の週で叩き台を作らない。既習連鎖を過去へ伸ばす改修はしない。
- 月の目標を年ごとに持つデータモデルの変更はしない。前の年度以前の週では月目標を表示も編集もしない。
- 過去の日を読み取り専用にしない。記録の補填を許す。
- 未来の週を今週＋3週より先へ広げない。
- コピー元のプレビュー、タイトルの全文検索、曜日の絞り込みは足さない。
- 取り込みで週や月の目標を一緒に持ってこない。
- 男女オンリーの3択と反転コピーの位置と並びを変えない。
- 既存データの移行はしない。週の保存キー（月曜ISO）と上書きの文書ID（実日付）はそのまま使う。

## 5. ux-designer への引き継ぎ

### 5.1 モックに必要な状態パターン

要望1（日レベルと週レベルの両方で同じ列を動かす）:

1. 今週を含む窓で今週を選んでいる（現状と同じ見え方に移動手段が足された状態）。
2. 「前の週」を1回押した後。窓が1週戻り、「今週へ戻る」が現れている。
3. 過去週の上書きあり日。
4. 過去週の上書きなし日。「記録なし」と「この日の記録を入力する」の1導線。
5. 到達下限で「前の週」が押せない。
6. 未来上限で「次の週」が押せない。
7. 「年月で飛ぶ」を開いた状態。選択肢は到達範囲内の年月だけ。
8. 今日と同じ年度の過去週の目標バー。月のセルがその週の月の目標を出している（見た目は現状の2セルのまま）。
9. 前の年度の週の目標バー。月のセルが無く、週の目標だけがある。

要望2（編集パネルの「他の日からコピー」）:

1. 候補0件（案内文）。
2. 少数。「おすすめ」だけ。
3. 多数。「おすすめ」3件と「探す」の年月と日。
4. 「去年の同じ頃」が無い（おすすめ2件）。
5. 「探す」で別の年月に切り替えた後。
6. 取り込み前の上書き確認（既存の流れ）。

### 5.2 意匠と配置の制約

- 週タブは既存の `.pk` の見た目のままにする。タブの数は4枠のまま。ラベル「yyyy/mm/dd〜」も変えない。
- 一歩移動はタブ列と同じ行の左右端に置き、列の高さを変えない。
- 「今週へ戻る」は窓が過去側にあるときだけ現れる。現れても列やツールバーの他の要素の位置が動かないようにする。
- 「年月で飛ぶ」は列の外（一歩移動の外側か列の直上）に置く。週タブ自体をドロップダウンにしない。
- 日レベルの列（`dayWeekSelector`、日付ピッカーより上の行）と週レベルの列（`weekPicker`）は同じ窓を見せる。片方だけ動く状態を作らない。
- 「他の日からコピー」は編集パネル内の現在位置（3択の下、叩き台の上）のまま。「おすすめ」と「探す」を縦に積み、取り込みボタンは1つ。
- 押せる部品の色と役割は `docs/design-system/component-spec.md` と `ui/styles/tokens.css` の意味ロール層に従う。新しい色を足さない。
- Hallmark の禁止事項（border-left の色帯、絵文字、汎用書体、紫やピンクのグラデーション）を持ち込まない。
- 対象幅は ux-designer の既定4幅（320、375、414、768px）とし、320px で一歩移動と4枠が同じ行に収まるかを最初に確かめる。収まらない場合はタブのラベルを短くするのではなく、一歩移動の幅を詰める。

### 5.3 文言

| 場所 | 文言 |
|---|---|
| 一歩移動 | 「前の週」「次の週」（アイコンにする場合も読み上げ名はこれ） |
| 戻る導線 | 「今週へ戻る」 |
| 長距離移動 | 「年月で飛ぶ」、選択肢は「2025年11月」 |
| 過去週の空の日 | 「この日の記録はありません。」と「この日の記録を入力する」 |
| コピー元の枠 | 「おすすめ」「探す」 |
| おすすめの関係語 | 「直近の火曜」（曜日名は実際の曜日）、「前回の練習日」、「去年の同じ頃」 |
| 探すの日のラベル | 「25日（火）：シュート強化」 |

## 6. architect への引き継ぎ

- 週配列の先頭は今週のまま固定する。`weeks[0]` の展開、`goalKeys.weekKey`、`goalKeys.monthArcKey` の意味を変えない。過去週は配列の前に足すのではなく、先頭固定のまま別の並びで持つか、表示順だけを窓で組み替える。
- 過去週の日は叩き台を作らず、`allCoachDays` が使う曜日テンプレを土台に上書きだけを合流する（`toEmptyDay` と `toAuthoredDay` の既存の合流をそのまま使う）。
- `goalsBar` の月セルは週ごとに「その週の月」のアーク月キーと目標テキストを持たせる。先頭週は現状の `goalKeys.monthArcKey` と同値になる。今日と同じ学校年度（週キーの月曜が4月1日から翌3月31日に入る）の外の週では月セルを出さない。
- 到達下限は「最古の上書き日を含む週」と「今週の4週前」の早い方。年月ジャンプの選択肢はこの範囲から作る。
- 目標の保存と上書きの削除のあとの再読込は不具合3の対応で廃止する。過去週の編集はその廃止のあとに出荷する。
- コピー元の「おすすめ」3件と「探す」の年月は `PREFILL` から決定論で作る。サーバは変えない。
- 既存テストのうち週の並びに触れるもの（`ui/week-start-sunday.test.mjs`、`ui/multiweek-day.test.mjs`、`ui/week-day-selection-sync.test.mjs`、`ui/day-toolbar-week-order.test.mjs`）は、先頭固定の前提を保てば既存の期待値のまま通る想定である。過去週を足したときに先頭が動かないことを、これらとは別に1本のテストで固定する。
