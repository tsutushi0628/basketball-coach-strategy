# 紅白戦チーム分け 要件（requirements）

> 対象リポジトリ = basketball-coach-strategy。Why は `product.md`、How は `design.md`、進捗は `tasks.md`。

## 1. 確定要件（オーナー裁定）

- スマホ前提。入口は独立URL `/scrimmage`（アプリ名「チーム分け」）で、ホーム画面に追加して直接開く。練習計画の画面は変更しない。
- 名簿はスプレッドシート「バスケ_選手名簿」が正本。既存列（選手ID／表示名／性別／学年／ポジション／利き手／本人の目標／在籍状態／メモ）に 身長cm／Tier／役割 を足す。ポジションは残すが読まない。
- 役割は複数選択（1セルにカンマ区切り）。語彙は ハンドラー／パサー／シューター／スラッシャー／リムアタッカー／エリートディフェンダー／リムプロテクター／リバウンダー の8語で、内部で 創造／得点手段／守備 の3群に分ける。
- Tier は 1〜5。実力 = Tier + 0.5×(学年−1)、上限なし。
- 男女別。当日欠席を外せる（既定は在籍中＝全員出席）。2〜3チーム、人数はチーム数で割り余りは先頭チームへ片寄せ。過去3回の同チームペアを減らす。「もう一回」は seed+1。
- 画面には Tier・役割・ポジション・身長・平均・警告・評価を出さない。結果はチーム A／B／C と選手名だけ。
- 面は3つ。①出欠とチーム数 ②結果（「もう一回」「この分けで決める」） ③名簿同期（管理者のみ）。ヘッダはアプリ名、男子／女子ピル、管理者のみ右端に下線「名簿」。
- 履歴に載るのは「この分けで決める」を押した分けだけ。

## 2. 非機能要件

- 全データ操作は Cloud Functions（Admin SDK）経由。Firestore rules は全 deny のまま。
- エンジンは外部依存ゼロの純関数で、同じ入力と同じ seed なら同じ出力（`Math.random`・`Date` 不使用）。
- 名簿同期は Sheets の取得失敗・差分 500 超のいずれでも Firestore を変えず、前回の名簿で分割が動く。
- 実名が置かれるのは本番 Firestore の `roster/{playerId}.name` だけ。seed・fixture・エミュレータ退避・spec には合成名と合成IDしか置かない。
- 同期後の名簿に 利き手・本人の目標・メモ・ポジション を持たない（読まない列は Firestore にも置かない）。

## 3. テスト要件

- エンジン（node:test・合成名簿）：決定論、seed 差で異なる分け、`n = teamCount〜20` × `teamCount = 2, 3` の全人数配分が `teamSizes` と一致、目的関数の各項、履歴罰点、不正入力の throw。
- 名簿正規化：役割セルの区切り6種と未知語・重複、Tier 範囲外→3、身長欠損→同性別中央値、性別欠落→skipped、`missing` の列名。
- API（モック db・実HTTP）：owner でない 403、`attendees` 越境 400、decide の分割検証 400、採番 `-1`・`-2`、sync の isAdmin 403・`sheetId` 書式 400・差分 500 超で 422 かつ roster 不変。
- 統合（エミュレータ実HTTP）：sync → GET /scrimmage → split → decide → 再 split の通し。HTML に合成名が出て Tier・役割・身長・学年の語が出ない。
- 練習計画の既存テスト・E2E は変更せずそのまま通す。

## 4. 受け入れ条件

- 同じ `roster`・`attendees`・`teamCount`・`history`・`seed` で `splitTeams` が同じ `teams` を返す。
- 13人・3チームで 5・4・4、13人・2チームで 7・6、5人・3チームで 2・2・1 になる。
- 実力合計差が 0.5 縮む交換は、役割欠けが1つ増えても採用される（100·0.5 = 50 > 40）。
- 過去3回同チームだったペアを含む分けは、それ以外が同点なら選ばれない。
- 面2の HTML とデータ島に Tier・役割・身長・学年・平均・警告・評価が含まれない。
- 当日欠席をチェックで外した選手が `teams` に現れない。
- 「もう一回」は `seed + 1` を送り、応答の `seed` が +1 されている。
- 履歴には「この分けで決める」を押した分けだけが保存される。
- 練習計画の既存画面の DOM と E2E に差分が出ない（`ui/pattern-timeline.mjs` と `ui/styles/` は無変更）。
- 名簿同期は管理者以外が 403、Sheets 失敗時は 502、差分 500 超は 422 で、いずれも `roster` が前回のまま残る。
- 同期後の `roster` に 利き手・本人の目標・メモ・ポジション が無い。
- seed・fixture・エミュレータ退避に実名が無い。
- `node --test engine functions` が通り、統合確認が PASS する。

## 5. やらないこと

- スプレッドシートへの書き戻し（欠席・チーム分け結果をシートに戻さない）。
- 名簿編集画面（名簿の直しはシート側で行う）。
- OAuth（コーチ個人の Google 認可）。ADC とサービスアカウント共有だけ。
- ウェブ公開CSV での読み取り。
- 学年による実力の上限、上級生の散らしを禁止事項にすること（いずれも重み付き罰点で扱う）。
- 1人入れ替え（相手を選んで交換する操作。「もう一回」だけで足りる）。
- manifest と Service Worker（ホーム画面追加はメタタグだけで行う）。
